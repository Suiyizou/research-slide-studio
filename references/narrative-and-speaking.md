# 研究问题、讲稿与末页去重

在梳理研究问题、审阅后半部分是否重复、撰写配套讲稿，或帮助用户理解文献及图示时阅读。只解释论文或单张图时，直接完成解释，不因此启动整套生图、重绘或改版流程。

## 先对齐文稿与本次范围

- 确认用户指的是哪一份 PPT，并读取完整页序、正文和必要备注；不要只根据上一轮聊天或一张截图推断最后几页。已经替换的文献页也要纳入讲稿。
- 本机 PowerPoint 的打开版本可能有未保存修改。可读取当前正文和预览核对，但不为取得素材擅自保存或覆盖用户文件。磁盘副本与打开版本有差异时，说明讲稿对应哪一版。
- “演讲稿能解释就不用改”意味着先解决表达。审阅重复页的实际画面，确定其各自职责；能讲清就保留，不额外换风格或重新生图。修改后的文件另存；仅生成讲稿时明确页面是否改动。

## 文献进展要落到过程和证据

对与研究主线直接相关的论文，优先说明：

1. **问题与材料**：研究什么问题，输入是原始观测、历史实验、配置、模型输出，还是已测性能？
2. **过程**：训练标签从哪里来；使用哪种学习、估计、选择或优化方法；新任务上怎样运行？
3. **产物**：输出预测数值、模型标签、候选误差、风险判断、下一配置，还是完整工作报告？
4. **证据与边界**：比较了什么基线，如何评价；实验支持了什么，不足以推出什么？

将这些关系画为流程或机制图；文献数量多时按研究能力组织，避免连续套用同一种表格或同一张框架图。具体可推进空间应从已核对的能力边界引出。

给未精读用户解释时，先区分容易混淆的对象，例如预测器与选择器、历史训练与新任务使用、模型输入与事后评价答案。可以用一个贯穿的小例子；明确例子是教学构造，不把示例分数、排名和曲线写成论文结果。无法核对的实验细节或提升数字不补写。

## 研究问题要能分别被实验回答

为每个问题明确“输入或可见信息 → 待判断对象 → 输出 → 对照条件 → 评价结果”。先检查两个问题是否实际使用相同实验回答，只是名称不同。

一种可用的递进是：

- **基础基线**：没有新增反馈时，已有信息可以达到什么程度？
- **核心方法或信息增量**：保持比较条件一致，只改变拟研究的因素，输出是否改善？
- **实际收益**：在完整流程和资源约束下，局部改善是否仍有净收益？
- **系统承载**：如何可靠执行、恢复、追溯和复核；用哪些系统指标检验？

根据课题采用其中适用的角色，可合并、增减或改用其他结构。建立基线不自动构成创新；把已有算法装进智能体也不自动证明方法更有效。

若同时研究“新信息是否有用”和“使用它是否节省搜索成本”，可先在相同已观察实验记录下隔离信息增量，再让策略在多轮搜索中形成各自轨迹，评价总成本。总成本按任务包含训练、验证、反馈处理、决策等开销，不能只用试验次数替代资源消耗。未执行候选的真实成绩或最终测试答案只能按协议用于训练标签或事后评价，不能泄漏给当前决策器。

## 重复页的保留与修改

共享模块不必然是内容重复；关键是每页是否回答了不同的问题。

| 页面职责 | 应讲重点 | 容易造成重复的讲法 |
|---|---|---|
| 背景、研究意义 | 为什么需要、为什么值得研究 | 提前详讲全部方法和实验 |
| 文献与不足 | 已有能力、待验证的具体增量 | 后面方案的完整预演 |
| 方法或消融页 | 输入变化、对照、预期证据 | 再次从背景开始讲 |
| 搜索或应用页 | 多轮决策、实际收益、成本核算 | 重讲局部特征的定义 |
| 系统页 | 调度与工具分工、失败处理、执行证据 | 用“系统跑通”代替方法有效性 |
| 总框架页 | 前述问题与模块的对应位置 | 逐个重复模块内部机制 |
| 总结页 | 预期或已证实贡献、实施优先级 | 又走一次完整反馈回路 |

用户允许保留页面时，优先在讲稿中安排一句区别和过渡。若两页没有独立信息、标题与实际验证目标矛盾，或仅靠口头解释仍会误导，局部合并或改写，并说明具体原因。不以“信息有用”“决策更优”等相近说法强凑新的独立问题。

## 逐页讲稿的交付

- 以实际页码和标题对应每页，正文用自然口语，说明“这页回答什么 → 沿图怎样看 → 应带走什么”。图密时按有意义的面板或路径指引，不念全部标签。
- 可直接朗读的正文与“不朗读”的指图提示、知识准备和注意事项分开。章节页只需短过渡；参考文献页用于查阅，无需逐条念。总框架与总结采用前述不同职责。
- 在研究问题之间说明“前一步解决了什么，还不能回答什么，因此需要下一步”。相似页面尤其要补这句过渡。
- 研究方案使用待检验表述；阶段汇报据实际证据陈述成果。分别标明文献结论、研究假设、示意图和教学例子。
- 时长服从实际字数、指图、停顿和用户要求，给出试讲可调整的估计，不把某次 22 页或 20 分钟固定成模板。
- 对用户不熟悉的术语和图形，先解释对象、轴或箭头、读图方法，再说明能支持什么结论。示意图不能作显著性或模型优劣的证据。
- 按需要附简短的“研究问题边界与常见追问”，解释基线与创新、局部提升与净收益、系统跑通与方法有效性的区别；不要把整段学习笔记塞进朗读正文。
- 交付时给出准确的讲稿和 PPT 文件链接。说明是否改页，并指出保留的相似页面怎样分别讲，不只说“已优化逻辑”。
