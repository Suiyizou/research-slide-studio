# 一比一构图与矢量重建

## 验收目标

按选定参考重建同一张设计：同画幅、同模块位置比例、同阅读路径、同对象信息、同连接关系和同视觉细度。用测量、对象清单和叠加对照落实一比一；不是只保留配色、圆角与几个大框。

科学内容先核对，再锁定选定参考。真实数据图由真实数据生成；示意图按一致的构造生成并标注。相互对应的残差、ACF、频谱来自同一条序列。标题、文字和公式在独立层校正，图形几何与科学关系保持一致。

**“一比一”指设计与语义保真。** 保留布局、比例、内容、连接、颜色关系和细节层次；规则圆形、直线、曲线和图标重绘为干净几何，清除参考中的毛边、残字与生成瑕疵。目标是精修重绘，不是把每个噪点变成路径。复杂图形按模块制作，不以自动描摹或图片包装换取表面相似。

按 [逐页提示词契约](page-image-prompt-contract.md) 的内容卡与检查记录核对科学对象和连接。一比一构图在科学关系修正后锁定；真实定量图区域使用真实图源，其数值、轨迹和不确定性以数据为准，不按生成参考中的虚构形状描摹。

## 1．建立对象清单

对每页记录主模块、输入输出、机制小图、坐标轴、图例、标签锚点、配置或状态标记、箭头与背景。每项包含边界框、层级、颜色和组名。先量位置、宽高和锚点，再开始绘图。

先确定用户需要怎样修改本页，再划定父组件与子对象。记录每个对象的唯一归属、父组、局部坐标和关联文字；连接记录起点、终点及边界锚点。完整类卡或注释卡包含可分别调整的外框、分隔线与文字，不能把矩形裁切范围直接当作组件边界。跨组件箭头单独重绘，归属双方的边缘不重复。

以用户认可的 [文献机制页](../assets/approved-research-examples/literature-mechanisms.png) 为完成度参照：每篇文献保留自己的数据 / 特征、方法结构、输出与验证说明；树、网络、矩阵、序列、标签和箭头都参与论证。候选输出区域具备对应信息，不退化成几个模型名和空白。

## 2．按语义重建真实 SVG

参考图保留只读，用于观察、测量和叠加；直接建立不带旧文字的图形层，再在独立文字层排版。OCR 仅辅助文字转录和粗定位，不能代替对象识别和几何设计。

主体科研图不采用“OCR 矩形去字 → 图像修补/inpaint → 连通区域切割 → VTracer/Potrace 整图描摹”的批量流水线。该过程会把擦字损伤、抗锯齿和纹理变成碎片，连通区域也不等于语义对象。自动描摹仅可辅助无字、独立小图标的初稿，随后清理路径、恢复规则形状并检查语义；不能作为整页重建完成的依据。

**把这条流水线拆成多个局部裁片仍不合格。** 去字图中的卡片裁片常含邻近箭头、外框或背景；描摹后再叠原生线，会复制这些残留。逐个组件也应按几何重绘：外框闭合、分隔线连续、箭头只绘制一次；核对每个组件之外没有不属于它的碎片。不能仅以“SVG 无 `<image>` / `<text>`”判断重建完成。

禁止把文字连同背景裁成 PNG 再包入 SVG、把字形转轮廓冒充可编辑文本、用白块或背景色矩形盖旧字。原设计的标题栏与卡片矩形正常重绘，背景与文字分层；背景不是遮盖残字的补丁。真实照片等合法来源素材按原用途处理。

- `viewBox` 与参考画幅一致；图标、模块、局部曲线、矩阵、图例和连接路径使用 `path`、`rect`、`circle`、`line`、`polygon`、`use` 等真实矢量图元。
- 主机制、曲线、坐标轴、图例、箭头分组清楚，保留稳定 ID；示例为 `feature_encoder`、`model_forest`、`candidate_output`、`residual_acf`。
- 对象按科学角色划分：节点用完整形状、连线用连续路径、箭头有明确端点、图标有完整轮廓。不要把一个节点拆成大量无意义色块，或把框线上的修补碎片当细节；散点按数据/已记录示意构造生成，不描摹模糊斑点。
- 非定量的机制路径按选定参考轨迹、控制点和线型重建，保留线宽、透明度和方向；数据曲线来自真实数据或已记录的示意构造，服从上述科学内容规则。模型机制按已核对参考分别重建，不用同一通用图标替换不同模型。
- 标题、说明、标签和公式的文字内容、边界框、基线、对齐和关联图元 ID 保存到独立文字坐标层。PPT 中使用原生文字；文字锚点与图形一致。

## 3．细节合并的明确边界

**用户说“散点太细，不必一个点一个对象”，只调整对象粒度，仍然输出矢量。**

| 内容 | 执行方式 |
|---|---|
| 密集散点 | 用多个 `circle/use` 组成一个语义组，或按颜色合并为复合路径；保留分布、点云边界、透明度和对应图例 |
| 热图或矩阵 | 同色单元合并路径或重复实例；保留行列、颜色关系和数值语义 |
| 网格、刻度、细纹理 | 合并线段或使用矢量 pattern；保留轴、尺度与图形层级 |
| 波形与频谱 | 每条曲线为连贯路径；数据驱动的形状保留真实关系 |
| 树、神经网络、流程图 | 节点与连线按语义成组，保留分支、深度和方向 |

合并可以减少 PPT 对象数量，不能减少关键信息，也不能改贴 PNG。`image`、`feImage`、`foreignObject`、base64 位图、整页截图和规则图片切片均不属于科研图矢量重建。用户封面、真实照片与科研机制图分开管理。

## 4．图形完成后对准文字

保留参考中的文字区域和视觉层级，再替换最终措辞。检查居中、边距、行高、基线、上下标和公式。文字增长通过精炼或拆页处理；调整相关模块后同步更新参考映射与连接线。中文与英文按内容需要混排。

图形和文字共用画布坐标及缩放变换，裁切偏移只应用一次。文字坐标层同时记录关联对象、对齐锚点、字体、字号、基线、行距和文本框内边距；OCR 外接框只是初值。显式设置 PPT 文本框边距与垂直对齐，按实际字形度量修正基线；不靠默认居中、自动缩字号或横向拉伸强行塞入识别框。长标签先调整文字区域及相邻对象，再渲染检查。

字体使用本机验证过的可读字形；检查中文、空格、英文、数学符号和上下标的 PowerPoint 实际效果。细节重建保留主框比例、树结构、网络连接、矩阵色块、图例及曲线对应关系。

## 5．进入 PowerPoint

纯图形 SVG 和文字坐标层共同作为几何来源。主体模块、图例、箭头转换为 PPT 原生形状、自由曲线或可解组的语义组；所有文字实际创建为原生文本框。源 SVG 的分组不能替代 PPT 内的对象分组，SVG 中的 `<text>` 不能替代 PPT 文本框。按 [PPT 编辑性契约](pptx-editability.md) 保存对象名称映射，先完成复杂样页的编辑、保存与重新打开测试，再批量制作。

用当前文稿接口完成导入、位置、分组和动画。按语义组组织节点与进入该模块的连线，移动节点后更新端点；检查 `p:cxnSp` 及连接器集合，保证连接线和节点同步。

## 6．逐页验收

1. 用相同分辨率渲染参考、SVG 和 PPT，保存三者并排图。
2. 参考与 SVG、SVG 与 PPT 分别做半透明叠加，检查边界框、图形轨迹、对象比例、锚点和线宽。
3. 放大关键局部核对对象清单，尤其是小图、模型结构、坐标轴、图例、输入输出和文字对准。检查残字、色块补丁、碎片路径、断线、重影和异常边界；在工作副本移动文字后，底层应仍是完整无字图形。按 [组件变更测试](pptx-editability.md#先做一页再批量) 改长文字、调整容器、移动并删除组件，核对干净边界和唯一归属。
4. 运行 `scripts/audit_design.py design-plan.json --pptx final.pptx`；运行 `scripts/audit_pptx.py final.pptx --plan design-plan.json --require-object-map` 核对最终 PPT 的全部标签与语义对象。记录 `pptx_comparison` 和 `pptx_overlay`，不能用参考/SVG 的对照冒充 PPT 验收。
5. 修复缺失或错位，重新渲染后标记本页 `reviewed: true`。对象计数作为结构证据，实际对照图作为构图与可读性证据。路径多、文件是 SVG、结构检查通过都不能证明重绘干净；语义对象、边缘质量和文字锚点必须逐项查看。

按 `initial`、`steps`、`keep_visible` 规划动画；标题、图例及必要参照保留，相关对象和连线同阶段出现。检查完整静态图以及初始、中间、最终播放状态。

## 交付图源

保存独立 SVG、文字坐标层、对象清单、参考图、提示词和对照图，并与 PPT 页码对应。SVG 原生导出后核对其内部图元；自定义路径由统一几何源维护。模板和组件位于 `../assets/faithful-vector-template.pptx`、`../assets/template-manifest.json` 与 `../assets/agent-workflow/`。
