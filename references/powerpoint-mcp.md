# PowerPoint MCP 实用经验

参考实现：https://github.com/ykuwai/ppt-mcp 。本流程验证过 Windows、PowerPoint Office16、ppt-mcp 2.3.0。版本和接口可能变化，使用时重新查询工具列表与参数，不照抄未经验证的命令。

## 连接与目标

安装、注册、握手是三个不同状态。只有实际 `initialize`、`list_tools` 和工具调用成功，才能声称 MCP 已可用。若当前聊天没有动态加载新工具，可在已授权的本机通过官方 MCP Python 客户端 `stdio_client` + `ClientSession` 连接已安装的服务器；不能把普通 COM 脚本声称为 MCP 调用。

保留用户的其他演示文稿。通过绝对路径打开目标，并在工具支持时显式传入 `presentation`。不要只依赖当前活动窗口。

`SaveAs` 后文件名改变，下一次调用可能命中另一份文稿。应重新打开或激活保存后的准确文件名，更新后续调用的 `presentation`，检查页数再导出。

## 显示与错误

- `with_window:false` 可以后台处理，但前台可能只显示空白窗口。用户要查看时用 `with_window:true` 打开最终文件，核对文件名、页数和页面对象。必要时按用户要求先新建空白文稿。
- 部分版本返回外层 `is_error:false`，内层文字 JSON 却含 `error`。两层都检查，失败后不得把后续步骤记作成功。
- COM 忙碌时先停止并行的 Office 操作，完成当前请求，再进行有界重试；不要无限重试或关闭用户无关文稿。

## 原生对象

从同一几何来源直接生成原生图元，文字单独创建为文本框，再组成可解组的语义组件。已有干净 SVG 可转换为原生形状，但须重建对象归属和文字，不能把自动转换产生的碎片直接交付。导入整页或分别导入多个组件 SVG 后仍只是图片；`addImage`、SVG 内部的 `<text>` 和图源包都不能证明 PPT 内可编辑。按照 [编辑性契约](pptx-editability.md) 先在副本里改长文字、扩容卡片、整体移动组件、更新连线并保存重开，再批量生成。

部分生成器给形状写入 `a:spLocks noGrp="1"`，导致分组失败。若确需分组，在工作副本中针对这些形状解除分组锁；保留其他锁、关系和文稿内容，再验证 PowerPoint 打开。不要全面清除包内保护属性。

分组后检查外部连接线端点是否仍落在可见边界。使用稳定、唯一的形状名称定位对象。动画尽量作用于整个语义组，避免文字、图标、边框分开出现。将进入模块的连线也归入对应阶段，并记录语义阶段、组名、触发方式和顺序；详细检查见 [曲线与动画](curves-and-animation.md)。

## 渲染与最终保存

使用目标文件名导出指定范围的幻灯片图片，检查返回图片数量。预期 22 页却返回 1 页时，先核对文稿目标，不要把它当作渲染成功。

实际图表可能忽略生成器的平滑属性。若原始数据应按折线呈现，可用图表工具或必要的定向 COM 修订将支持平滑属性的折线／散点序列设为 `Smooth=False`，不要对柱状等不支持该属性的图表批量设置，保存后重新导出；如需这一回退，记录它与 MCP 各自完成的操作。

最终交付前检查保存文件中的页数、原生对象数量、字体、动画与连接关系，并按当前演示文稿技能要求进行包结构验证。最后展示完整的最终文件，而不是后台窗口或空白新建页。
